## Objetivo

Padronize o projeto:

```text
gfm-template-cms-azure
```

seguindo o mesmo padrão de engenharia e desenvolvimento utilizado em:

```text
gfm-template-cms-aws
```

Porém, existe uma regra fundamental:

- O **gfm-template-cms-aws** deve ser utilizado como referência de estrutura, organização, padrões de desenvolvimento, documentação, Agents, Skills, Quality Gates, GitFlow, testes, Docker, observabilidade e governança.
- O **gfm-template-cms-azure** deve manter suas próprias regras de negócio, arquitetura e decisões específicas de Azure.
- Não transforme o projeto Azure em um projeto AWS.
- Tudo que for específico de AWS deverá ser analisado e adaptado para o serviço ou padrão equivalente no Azure.
- Utilize o **Kit IA Dev** como fonte oficial para Agents, Skills, padrões, documentação, Knowledge Dictionary e processo de desenvolvimento.

A ideia é:

```text
gfm-template-cms-aws
        ↓
Padrão de desenvolvimento
Estrutura
Governança
Agents
Skills
Quality Gates
Testes
Documentação
GitFlow
Docker
Observabilidade
        ↓
ADAPTAR PARA AZURE
        ↓
gfm-template-cms-azure
```

O resultado deverá manter:

```text
GFM.Template.CMS
+
regras de negócio do projeto Azure
+
arquitetura Azure
+
padrão de desenvolvimento do projeto AWS
+

```

Analise primeiro os três diretórios:

```text
D:\Empresa\GFMaurila\projetos\gfm-template-cms-aws

D:\Empresa\GFMaurila\projetos\Kit-IA-Dev
```

Compare o projeto AWS com o projeto Azure e identifique tudo que está faltando no Azure para que ambos tenham o mesmo nível de padronização.


Não copie configurações AWS diretamente para o projeto Azure.

Adapte tudo que for específico de cloud para Azure.

Ao final, o projeto:

```text
D:\Empresa\GFMaurila\projetos\gfm-template-cms-azure
```

```text

```

mas utilizando **Azure como plataforma de cloud** e preservando integralmente as regras de negócio e decisões arquiteturais específicas do projeto Azure.
